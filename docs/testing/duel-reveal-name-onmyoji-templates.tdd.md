# 斗技双方揭示名称与阴阳师固定槽位：TDD 证据

日期：2026-08-02

## RED

- 新增几何测试后，代码尚不存在对方揭示名称 ROI、分辨率缩放与六个阴阳师槽位 ROI，测试因导入失败。
- 新增流程测试后，双方锁定名称无法写入对方账本；我方名称不一致、对方仍在选择和 AUTO 缺少我方点击账本的拒绝路径同时被固定。
- 按真实截图 OCR 分数 `0.613/0.668` 下调测试数据后，旧的 `0.90` 判断无法识别已正确解析的 `399/583`。
- 去掉已消失的“对方已确定”文字信号后，旧门禁无法处理真实双方亮相画面。
- OBSERVE/RECOMMEND 没有预先存在的我方点击账本时，旧实现无法从同一揭示帧学习双方身份；晚到的揭示也无法解除人工身份的 fail-closed 阻塞。
- 阴阳师提取工具在实现前不存在；测试要求六张 roster 参考图与至多一张显式标注的 selected 模板严格分离。
- 新增“对方选择中/对方已确定”实图后，RED 证明仅有对方状态文字时旧分类器会错误返回高置信 `OPPONENT_PICK`，阴阳师阶段还会提前返回 `READY`；连续三帧可错误提交我方 pending 选择。
- RED 同时证明“我方已确定 + 对方已确定文字仍显示”时，旧揭示门禁会过早调用左右名称 OCR。

## GREEN

- 基准画布新增左侧 `(170,150,40,165)` 与右侧 `(680,150,40,165)` 名称 ROI；使用等比居中、前缘 floor/后缘 ceil 缩放，并在 OCR 前归一回 `40×165`。
- 每个主循环只在同一截图同时读取左右名称，不在 helper 内额外截图；连续三帧同一 pair 才提交，避免跨转场拼接。
- 同一锁定揭示画面提交后进入“本轮已消费”状态；即使持续显示 8 帧也只入账一次，只有明确识别到下一轮可点击的确认按钮后才重新布防。
- `对方选择中`、`对方已确定` 只描述对方进度，不拥有我方回合：与我方可点击“确定”同时出现时仍是 `SELF_PICK`；单独出现时不产生相位，也不能触发 pending 提交或阴阳师阶段 `READY`。
- 名称揭示新增双状态消失门禁：只有我方按钮为“已确定”，且“对方选择中/对方已确定”两个文案都消失后才开始三帧双名称识别。普通 pending 的账本提交点另行要求原始 `confirm_locked` 信号；`READY/BATTLE` 不再作为泛化替代证据，第五手进入阴阳师仍使用其独立、稳定的页面证明路径。
- 门禁要求我方“已确定”、主动确认按钮消失、对方“选择中”遮罩消失、非阴阳师阶段；实际亮相后已经消失的旧“对方已确定”文字不再是必需条件。
- 低原始 OCR 分只允许 exact/substring 且同帧至少两个独立裁剪一致；fuzzy 仍要求配置阈值。AUTO 仍必须与我方点击账本一致，且真正点击“确定”的 `>=0.98` 门禁未降低。
- OBSERVE/RECOMMEND 可从锁定 pair 同时学习我方与对方；AUTO 绝不从 OCR 发明缺失的我方选择。写入后账本立即具备下一手推荐上下文。
- 第二张截图曾生成六张 `_reference/*-roster.png`，并显式生成 `yorimitsu-selected.png`；这些文件保留为离线参考，不再参与运行时流程。
- 重复提取后的七个文件 SHA-256 保持一致。
